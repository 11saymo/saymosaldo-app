Политика конфиденциальности

Дата вступления в силу: 22 ноября 2026 года

Эта страница объясняет, как SaymoSaldo обрабатывает данные при использовании личного финансового аккаунта.

Коротко:
  • Для входа используется логин и пароль; адрес электронной почты не запрашивается.
  • Пароли обрабатываются Supabase Auth и не сохраняются в таблицах финансовых данных SaymoSaldo.
  • Финансовые записи хранятся в облачной базе данных аккаунта и в локальном хранилище браузера для быстрой работы.
  • Доступ к облачным записям ограничен идентификатором вошедшего пользователя с помощью Row Level Security (RLS).
  • Код восстановления показывается один раз. На сервере хранится только его SHA-256 хеш.

1. Данные аккаунта

При регистрации создаются логин и пароль. Для внутренней работы сервиса логин преобразуется в технический адрес на домене accounts.saymosaldo.app; это не почтовый ящик, письма на него не отправляются и личный адрес электронной почты не требуется. Supabase Auth хранит учётную запись и проверяет пароль. SaymoSaldo не получает и не хранит пароль в открытом виде.

2. Финансовые данные и синхронизация

В аккаунте могут сохраняться операции доходов и расходов, категории, цели, лимиты, регулярные платежи, долги и история общения с локальным финансовым помощником. Эти данные передаются по HTTPS в базу данных Supabase и синхронизируются между устройствами, на которых вы вошли в один аккаунт. Политики RLS ограничивают чтение и изменение записей владельцем аккаунта. Клиентское приложение также сохраняет локальную копию в браузере, чтобы интерфейс быстро открывался и мог временно работать без сети.

3. Локальное хранение и безопасность устройства

Сессия входа и локальная копия финансовых записей сохраняются в хранилище браузера. Эти данные не зашифрованы отдельным паролем SaymoSaldo. Защищайте телефон блокировкой экрана, не используйте приложение на чужих или общедоступных устройствах и выходите из аккаунта после работы на общем устройстве. Не вводите в приложение PIN-коды, CVV, пароли от банков и другие секреты.

4. Код восстановления

При регистрации создаётся случайный код восстановления. Он показывается только один раз; сохраните его в надёжном месте отдельно от устройства. Если вы забудете пароль, этот код позволит задать новый пароль. После восстановления выдаётся новый код, а прежний перестаёт действовать. Если вы потеряете и пароль, и код восстановления, автоматическое восстановление аккаунта невозможно, поскольку электронная почта не используется.

5. Передача данных сторонним сервисам

Для авторизации, облачного хранения и синхронизации используется инфраструктура Supabase. Сайт размещён на GitHub Pages. SaymoSaldo не отправляет финансовые записи внешним ИИ-сервисам, рекламным или аналитическим системам. GitHub и Supabase могут обрабатывать технические сведения, необходимые для предоставления и защиты своих сервисов, в соответствии со своими политиками конфиденциальности: GitHub и Supabase.

6. Резервные копии

Вы можете вручную экспортировать финансовые данные в файл через раздел «Ещё → Данные». Такой файл содержит личную финансовую информацию и историю помощника. Храните его в надёжном месте и не передавайте посторонним. Облачная синхронизация не заменяет отдельную резервную копию, которую вы контролируете самостоятельно.

7. Выход и удаление данных

Кнопка «Выйти» завершает сессию на текущем устройстве. Локальная копия данных этого аккаунта остаётся в хранилище браузера, чтобы не потерять изменения при временных сбоях сети. Не используйте выход как способ безопасного удаления локальных данных на общем устройстве. Для полного удаления аккаунта и связанных с ним облачных данных обратитесь через страницу обратной связи проекта; перед запросом сохраните резервную копию, если хотите оставить записи.

8. Изменения политики и обратная связь

При изменении способов хранения или обработки данных эта страница будет обновлена. Вопросы и замечания можно направить через GitHub проекта.
