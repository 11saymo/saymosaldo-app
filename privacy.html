Политика конфиденциальности

Дата вступления в силу: 23 ноября 2026 года

Эта страница объясняет, как MUNORA обрабатывает данные при использовании личного финансового аккаунта и входе через Google.

Коротко:
  • Вход в MUNORA выполняется через Google. Пользователь сам выбирает Google-аккаунт и подтверждает вход.
  • Для идентификации запрашиваются только базовые сведения Google: подтверждение личности, адрес электронной почты, имя и фотография профиля. Доступ к Gmail, Google Диску, контактам и другим сервисам Google не запрашивается.
  • MUNORA не получает пароль от Google. Проверку личности и сессии выполняет Supabase Auth.
  • Финансовые записи хранятся в облачной базе данных аккаунта и в локальном хранилище браузера для быстрой работы.
  • Доступ к облачным записям ограничен идентификатором вошедшего пользователя с помощью Row Level Security (RLS).

1. Данные аккаунта и вход через Google

Для регистрации и входа используется Google OAuth. После того как пользователь выбирает аккаунт Google и подтверждает вход, MUNORA получает только данные, необходимые для идентификации: уникальный идентификатор пользователя у провайдера, подтверждённый адрес электронной почты, имя и фотографию профиля (если они доступны). Эти сведения обрабатываются через Supabase Auth и используются для создания аккаунта, входа и отображения имени пользователя.

MUNORA не получает и не хранит пароль от Google и не запрашивает доступ к Gmail, Google Диску, контактам, календарю или другим данным Google. Вход запрашивает только стандартные области идентификации openid, email и profile. Пользователь может отозвать разрешение на вход через настройки безопасности своего Google-аккаунта.

2. Финансовые данные и синхронизация

В аккаунте могут сохраняться операции доходов и расходов, категории, цели, лимиты, регулярные платежи, долги и история общения с локальным финансовым помощником. Эти данные передаются по HTTPS в базу данных Supabase и синхронизируются между устройствами, на которых вы вошли в один аккаунт. Политики RLS ограничивают чтение и изменение записей владельцем аккаунта. Клиентское приложение также сохраняет локальную копию в браузере, чтобы интерфейс быстро открывался и мог временно работать без сети.

3. Локальное хранение и безопасность устройства

Сессия входа и локальная копия финансовых записей сохраняются в хранилище браузера. Токены сессии и финансовая копия не зашифрованы отдельным паролем MUNORA. Защищайте телефон блокировкой экрана, не используйте приложение на чужих или общедоступных устройствах и выходите из аккаунта после работы на общем устройстве. Не вводите в приложение PIN-коды, CVV, пароли от банков и другие секреты.

4. Восстановление доступа

В текущей версии MUNORA вход выполняется через Google. Отдельный пароль MUNORA и отдельный код восстановления не используются. Если вы не можете войти в Google-аккаунт или забыли его пароль, воспользуйтесь средствами восстановления аккаунта Google: восстановление Google-аккаунта.

5. Передача данных сторонним сервисам

Для авторизации и хранения минимальных данных профиля используется Google через Supabase Auth; для облачного хранения финансовых записей и синхронизации используется инфраструктура Supabase. Сайт размещён на GitHub Pages. Данные Google используются только для входа и отображения профиля и не используются для доступа к другим сервисам Google. Финансовые записи не передаются Google, внешним ИИ-сервисам, рекламным или аналитическим системам. GitHub и Supabase могут обрабатывать технические сведения, необходимые для предоставления и защиты своих сервисов, в соответствии со своими политиками конфиденциальности: GitHub и Supabase.

6. Резервные копии

При первой записи облачных данных база может сохранить её исходное состояние, а при последующих изменениях — предыдущее состояние. Автоматический снимок создаётся не чаще одного раза за 24 часа для одного аккаунта; система хранит не более 30 последних снимков. Кроме того, вы можете вручную экспортировать финансовые данные в файл через раздел «Ещё → Данные». Экспортированный файл содержит личную финансовую информацию и историю помощника. Храните его в надёжном месте и не передавайте посторонним. При восстановлении из снимка текущие данные предварительно сохраняются в отдельную контрольную копию. Эти механизмы не заменяют отдельный экспорт, который вы храните самостоятельно.

7. Выход и удаление данных

Кнопка «Выйти» завершает сессию на текущем устройстве. Локальная копия данных этого аккаунта остаётся в хранилище браузера, чтобы не потерять изменения при временных сбоях сети. Не используйте выход как способ безопасного удаления локальных данных на общем устройстве.

Удалить аккаунт и связанные облачные данные можно самостоятельно в приложении: «Ещё → Данные → Удалить аккаунт и данные». Для подтверждения требуется недавний вход через Google (не старше 10 минут) и явное подтверждение удаления. После удаления аккаунта удаляются профиль авторизации, облачные финансовые записи и резервные копии. Локальная копия на текущем устройстве также очищается приложением. Локальные копии на других устройствах нельзя удалить удалённо: очистите данные сайта MUNORA в настройках браузера на каждом таком устройстве. Перед удалением скачайте резервную копию, если хотите сохранить свои записи. Удаление необратимо.

Не отправляйте персональные или финансовые данные через публичные GitHub Issues.

8. Подробно о данных Google и целях их использования

При нажатии кнопки входа MUNORA перенаправляет пользователя в Google для аутентификации. В рамках стандартных областей OAuth openid, email и profile приложение получает подтверждение аутентификации и минимальные сведения профиля: уникальный идентификатор Google, адрес электронной почты, имя и, если предоставлена, фотографию профиля. Эти сведения используются исключительно для создания и идентификации аккаунта, входа, поддержания пользовательской сессии и отображения профиля внутри MUNORA.

MUNORA не получает данные Gmail, содержимое писем, файлы Google Диска, контакты, события календаря, историю поиска, платёжные данные Google или иные данные Google API. Приложение не продаёт и не использует сведения Google для рекламы, таргетинга, кредитного скоринга или профилирования. Данные Google не передаются третьим лицам для независимого использования и не используются для обучения моделей искусственного интеллекта.

Полученные данные профиля обрабатываются Supabase Auth для управления учётной записью и сессией. Финансовые записи пользователя хранятся отдельно в базе данных Supabase и в локальном хранилище браузера. Google не получает доступ к финансовым записям. Доступ к облачным финансовым записям ограничивается политиками Row Level Security для соответствующего аккаунта.

MUNORA использует данные Google только в объёме, необходимом для предоставления и улучшения функций входа и аккаунта, и соблюдает требования Google API Services User Data Policy, включая требования Limited Use. Данные Google не используются для целей, несовместимых с целью предоставления запрошенной пользователем функции.

9. Сроки хранения и удаление данных

Данные профиля аккаунта сохраняются, пока аккаунт активен или пока это необходимо для предоставления входа и работы сервиса. Сессионные токены хранятся в браузере в рамках механизма аутентификации Supabase. Финансовые записи и резервные копии хранятся до их удаления пользователем или удаления аккаунта, с учётом описанных выше ограничений резервного хранения. Пользователь может отозвать доступ MUNORA к своему Google-аккаунту в настройках безопасности Google и удалить аккаунт MUNORA через функцию удаления аккаунта в приложении.

После удаления аккаунта связанные облачные финансовые данные и резервные копии удаляются из активной базы данных согласно процедуре удаления. Локальные копии на других устройствах пользователь должен удалить самостоятельно, очистив данные сайта в браузере. Для вопросов об удалении или обработке данных можно обратиться по адресу should.poject@gmail.com.

10. Передача данных и сторонние обработчики

Supabase обрабатывает данные аутентификации и хранит облачные финансовые записи от имени MUNORA; GitHub Pages предоставляет хостинг статического сайта. Эти поставщики могут обрабатывать техническую информацию в целях безопасности, доступности и работы инфраструктуры в соответствии со своими условиями и политиками конфиденциальности. MUNORA не продаёт личные данные и не передаёт финансовые записи рекламным сетям.
